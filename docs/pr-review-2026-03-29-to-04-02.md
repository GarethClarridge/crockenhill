## 🟡 Patterns to Address

### 1. **Form Request Classes Missing (PR #257)**

- **Issue**: Validation inlined in controller with `$request->validate()` instead of a `SermonIndexRequest` class
- **Project convention**: CLAUDE.md explicitly requires Form Request classes for all validation
- **Impact**: Violated on #257; check #251 (admin filters) and #258 (Mailgun) for same pattern
- **Fix**: Create dedicated `SermonIndexRequest` and similar classes for other endpoints

### 2. **Per-Page Limit Not Bounded (PR #257) — CRITICAL**

- **Issue**: `per_page` validation allows `nullable|integer` with **no max**
- **Risk**: Attacker sends `per_page=999999`, forces full table load → DoS
- **PR docblock claim**: "Add strict input validation to Sermon API" — but this is incomplete
- **Fix**: Add `max:100` (or appropriate ceiling) to `per_page` rule immediately

### 3. **MySQL-Only DB Constraints (PRs #256, #250)**

- **Issue**: Constraints gated on `if (DB::getDriverName() === 'mysql')` but CI likely uses SQLite
- **Impact**: DB-level tests silently skip on SQLite; no constraint coverage in CI
- **Affected tests**:
  - `DurationConstraintTest` (#256) — tests for negative duration rejection, end >= start invariants
  - `SpeakerIntegrityTest` (#250) — tests for quality_score/threshold bounds
- **Options**:
  - Add `@requires extension pdo_mysql` to constraint-testing methods, or
  - Use `markTestSkipped()` explicitly in test setup
- **Current state**: Constraints work in production (MySQL) but test coverage is incomplete

### 4. **Unused `validationRules()` Methods (PRs #256, #250)**

- **Issue**: Models define static `validationRules()` but nothing calls them outside tests
- **Example**: `SpeakerProfile::validationRules()` and `SpeakerSample::validationRules()` defined but not wired into Form Requests
- **Pattern**: Define rules but don't wire them into controllers/requests — violates DRY
- **Fix**: Either use them in Form Requests (see #1) or remove them

### 5. **Test Coverage Gaps**

Per project rule "Every change must have accompanying tests":

- **PR #254** (Breadcrumb JSON-LD): No tests verifying schema output; relies on manual verification
- **PR #253** (Sitemap optimization): No integration test for the refactored `map()` call; optimization is invisible
- **PR #251** (Admin filters): Visual refactor, but no test asserting Clear Filters behavior
- **PR #248** (Semantic HTML): No tests for `<time>` tag rendering or `preacher_url` schema presence

### 6. **Nullable Type Regressions (PR #245)**

- **`humanDate` accessor**: Changed from nullable `?string` to non-nullable `string`
- **Risk**: If `$sermon->date` is null (nullable column), accessor throws; old code returned null gracefully
- **Code**: 
  ```php
  // Old: protected function getHumanDateAttribute(): ?string { ... }
  // New: fn (): string => $this->date->format('j F Y')
  ```
  - If `$this->date` is null, the second form throws
- **Action**: Verify `sermons.date` column is NOT nullable, or revert to `?string` return type

### 7. **Dead Code & No-Ops (PRs #253, #261)**

- **`clearInternalCaches()`** in `SermonStorageService` (#253): Public method wraps null case that "currently has no logic"
  - Comment: `// Logic for clearing broad caches if needed (none currently)`
  - This is a no-op that adds API surface
- **`cdnEndpoint` property** (#261): Loses `@var ?string` annotation, no cast safeguard
  - Type annotation removed; `config()` can return arrays but code trusts it's always a string
- **Fix**: Remove no-ops or add TODO comments + tests validating they'll be used

### 8. **Duplicate Markup (PR #259)**

- **`x-admin.filter-bar` component**: Clear Filters button defined in TWO branches:
  ```blade
  @isset($actions)
    {{-- Clear Filters button here --}}
  @else
    {{-- Clear Filters button here (duplicate) --}}
  @endif
  ```
- **Risk**: Future changes to button markup require two edits; maintenance burden
- **Fix**: Extract into a sub-partial or use a Blade fragment

### 9. **Service Singleton Hazards (PRs #261, #247)**

- **Issue**: Config values cached in constructor properties; if service is a singleton, mid-request config changes won't propagate
- **Risk**: Low in web requests, but could surprise in queue workers or artisan commands
- **Example** (PR #261): `SermonStorageService` caches `config('filesystems.disks.s3.key')` at construction
- **Mitigation**: Comment explaining singleton assumption, or add `refreshConfig()` escape hatch (already present in #261)

### 10. **Validation Pattern Inconsistencies (PR #258)**

- **Mailgun inbound validation**: Uses `max:` rules but doesn't prevent true DoS
  - `max:500000` on request body happens **after** full payload parsed into memory
  - True DoS prevention requires middleware-level `Content-Length` or `post_max_size` checks
- **Assessment**: Still valuable as defense-in-depth, but doesn't fully solve the problem
