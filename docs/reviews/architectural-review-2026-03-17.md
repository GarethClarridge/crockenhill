## 2. Boundary / Coupling Problems

- Core domain state is shared through mutable JSON blobs across tables and services, not typed aggregates. `processing_metadata`, `import_metadata`, `metadata`, and `thumbnail_metadata` are read and rewritten in multiple places such as [app/Services/InboundEmailImportService.php:26](/Users/garethclarridge/Projects/crockenhill/app/Services/InboundEmailImportService.php#L26), [app/Services/ChurchServiceCanonicalUpdateService.php:22](/Users/garethclarridge/Projects/crockenhill/app/Services/ChurchServiceCanonicalUpdateService.php#L22), and [app/Services/MediaProcessingIdentityResolver.php:18](/Users/garethclarridge/Projects/crockenhill/app/Services/MediaProcessingIdentityResolver.php#L18).
- Eloquent models cross into infrastructure and workflow concerns. `Sermon` resolves services from the container and reads storage-backed transcript content in accessors, while `MediaProcessingLog` owns process-state transitions and manual-review state in [app/Models/Sermon.php:163](/Users/garethclarridge/Projects/crockenhill/app/Models/Sermon.php#L163), [app/Models/Sermon.php:413](/Users/garethclarridge/Projects/crockenhill/app/Models/Sermon.php#L413), and [app/Models/MediaProcessingLog.php:329](/Users/garethclarridge/Projects/crockenhill/app/Models/MediaProcessingLog.php#L329).

## 3. Top Tech-Debt Items

- Severity: High. Fragmented media-processing orchestration in [app/Services/UnifiedMediaProcessor.php:21](/Users/garethclarridge/Projects/crockenhill/app/Services/UnifiedMediaProcessor.php#L21), [app/Services/SermonJobPipelineService.php:30](/Users/garethclarridge/Projects/crockenhill/app/Services/SermonJobPipelineService.php#L30), and [app/Services/ProcessingPipelineBuilder.php:39](/Users/garethclarridge/Projects/crockenhill/app/Services/ProcessingPipelineBuilder.php#L39). Evidence: processor creates logs, stores files, dispatches chains, handles status/retry/cancel; pipeline service also dispatches/retries/restarts; builder hardcodes raw job sequences. Impact: changing one stage or retry rule requires edits in several layers, with state names duplicated as strings. Suggested refactor direction: introduce a single workflow coordinator/state machine with declarative stage definitions and one owner for dispatch/retry semantics.
- Severity: High. Monolithic OoS alignment engine in [app/Services/OosAlignmentService.php:19](/Users/garethclarridge/Projects/crockenhill/app/Services/OosAlignmentService.php#L19) and [app/Services/OosAlignmentService.php:60](/Users/garethclarridge/Projects/crockenhill/app/Services/OosAlignmentService.php#L60). Evidence: one 1,066-line service resolves identity, loads data, mutates sections, scores matches, applies review flags, persists confidence, and syncs review state inside one transaction. Impact: very high change risk in a critical workflow; hard to isolate regressions or reason about correctness. Suggested refactor direction: split into smaller alignment strategies plus an immutable result object, with persistence/review-state writing moved to separate collaborators.
- Severity: High. Service-aware models in [app/Models/Sermon.php:163](/Users/garethclarridge/Projects/crockenhill/app/Models/Sermon.php#L163), [app/Models/Sermon.php:413](/Users/garethclarridge/Projects/crockenhill/app/Models/Sermon.php#L413), and [app/Models/MediaProcessingLog.php:381](/Users/garethclarridge/Projects/crockenhill/app/Models/MediaProcessingLog.php#L381). Evidence: model accessors call container services and storage, while `MediaProcessingLog` manages workflow transitions and review metadata. Impact: hidden I/O in reads, harder serialization/caching, and business state changes buried in persistence models. Suggested refactor direction: keep models to relations/scopes/state primitives; move URL/transcript retrieval and workflow mutation into dedicated read-model and application services.
- Severity: Medium. Fat Livewire admin components in [app/Livewire/Admin/ChurchServices/ServiceReviewDashboard.php:53](/Users/garethclarridge/Projects/crockenhill/app/Livewire/Admin/ChurchServices/ServiceReviewDashboard.php#L53), [app/Livewire/Admin/ChurchServices/ManageChurchService.php:193](/Users/garethclarridge/Projects/crockenhill/app/Livewire/Admin/ChurchServices/ManageChurchService.php#L193), and [app/Livewire/Admin/ChurchServices/ShowChurchService.php:45](/Users/garethclarridge/Projects/crockenhill/app/Livewire/Admin/ChurchServices/ShowChurchService.php#L45). Evidence: authorization, validation, metadata mutation, transactions, queue dispatch, and reporting/timeline assembly all happen inside UI classes. Impact: UI changes can unintentionally alter domain rules, and the domain logic is harder to reuse outside Livewire. Suggested refactor direction: extract actions/use-cases plus read-only view models; keep components focused on state binding and user interaction.
- Severity: Medium. JSON metadata as cross-module contract in [app/Services/InboundEmailImportService.php:117](/Users/garethclarridge/Projects/crockenhill/app/Services/InboundEmailImportService.php#L117), [app/Services/ChurchServiceCanonicalUpdateService.php:45](/Users/garethclarridge/Projects/crockenhill/app/Services/ChurchServiceCanonicalUpdateService.php#L45), [app/Services/ServiceSectionSyncService.php:146](/Users/garethclarridge/Projects/crockenhill/app/Services/ServiceSectionSyncService.php#L146), and [app/Services/MediaProcessingIdentityResolver.php:20](/Users/garethclarridge/Projects/crockenhill/app/Services/MediaProcessingIdentityResolver.php#L20). Evidence: key behavior depends on array shapes and magic keys like `manual_review`, `canonical_conflict`, `review_flags`, and `extracted_service`. Impact: low discoverability, weak queryability, and no versioned contract between async jobs/import flows. Suggested refactor direction: normalize critical subdomains into tables or typed DTO/value objects first for review decisions, parser results, publication audits, and reconciliation triggers.

## 5. Open Questions / Assumptions

- I treated this as a static read-only review and did not run the suite or queue workers.
- I’m assuming the observer + event-listener reconciliation paths are deliberate eventual-consistency mechanisms, not accidental duplication.
- I’m assuming the JSON metadata structures are effectively part of the app’s internal contract; if they are temporary migration scaffolding, the refactor priority changes.
- I’m not sure whether the catch-all page/presenter stack is still strategic or mostly legacy compatibility; that affects whether to simplify it or leave it alone.
