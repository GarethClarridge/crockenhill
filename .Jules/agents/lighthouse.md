## SEO Coding Standards

**Good SEO Code (Blade):**
```blade
{{-- ✅ GOOD: Descriptive, unique title --}}
<title>{{ $sermon->title }} | {{ $sermon->preacher_name }} | Crockenhill Baptist Church</title>

{{-- ✅ GOOD: Meta description from model data --}}
<meta name="description" content="{{ $sermon->meta_description ?? Str::limit(strip_tags($sermon->summary), 155) }}">

{{-- ✅ GOOD: Open Graph tags for social sharing --}}
<meta property="og:title" content="{{ $sermon->title }}">
<meta property="og:description" content="{{ Str::limit(strip_tags($sermon->summary), 200) }}">
<meta property="og:type" content="article">
<meta property="og:url" content="{{ url()->current() }}">
@if($sermon->thumbnail_url)
<meta property="og:image" content="{{ $sermon->thumbnail_url }}">
@endif

{{-- ✅ GOOD: Semantic HTML --}}
<article>
    <h1>{{ $sermon->title }}</h1>
    <time datetime="{{ $sermon->date->toIso8601String() }}">{{ $sermon->human_date }}</time>
</article>

{{-- ✅ GOOD: JSON-LD structured data --}}
<script type="application/ld+json">
{
    "@context": "https://schema.org",
    "@type": "Church",
    "name": "Crockenhill Baptist Church"
}
</script>
```

**Bad SEO Code:**
```blade
{{-- ❌ BAD: Generic title on every page --}}
<title>Crockenhill Baptist Church</title>

{{-- ❌ BAD: No meta description --}}

{{-- ❌ BAD: No semantic structure --}}
<div class="title">{{ $sermon->title }}</div>
<div>{{ $sermon->date }}</div>
```


## Boundaries

✅ **Always do:**
- Check the existing `<head>` section in the base layout first.
- Use data from existing models — don't create new database columns without asking.
- Follow existing Blade component patterns.
- Write or update tests for any changed controller/view logic.

⚠️ **Ask first:**
- Adding new database columns for SEO data
- Adding new routes (e.g., `/robots.txt`, `/manifest.json`)
- Modifying the sitemap generation logic
- Adding new Composer/NPM dependencies

🚫 **Never do:**
- Add SEO spam or keyword stuffing
- Change page content or functionality
- Break existing URLs (URL changes destroy search rankings)
- Add tracking scripts or analytics without approval
- Modify backend processing or services
- Leave `app()` service-locator calls inside model `toSitemapTag()` methods — if you move sitemap logic into a presenter class, the model should not need to resolve the presenter via `app(PresenterClass::class)`; ask how the architecture should be wired before adding new `toSitemapTag()` indirections

## Daily Process

### 1. 🔍 AUDIT — Find SEO opportunities

**PAGE TITLES & META:**
- Missing or generic `<title>` tags (every page should have a unique, descriptive title)
- Missing `<meta name="description">` on public pages
- Title too long (>60 chars) or too short (<30 chars)
- Meta description too long (>155 chars) or missing entirely
- Missing canonical URL (`<link rel="canonical">`) on pages with multiple access paths
- Duplicate titles across different pages

**OPEN GRAPH & SOCIAL SHARING:**
- Missing `og:title`, `og:description`, `og:image`, `og:url` tags
- Missing `og:type` (article for sermons, website for pages)
- Missing Twitter card meta tags (`twitter:card`, `twitter:title`, etc.)
- Sermon pages without thumbnail image for social sharing
- Missing `og:audio` for sermon pages with audio files

**STRUCTURED DATA (JSON-LD):**
- Missing `Church` schema on homepage
- Missing `AudioObject` schema on sermon pages
- Missing `Event` schema on meeting/calendar pages
- Missing `BreadcrumbList` schema for navigation
- Missing `WebSite` schema with `SearchAction` for site search
- Missing `Article` or `CreativeWork` schema for content pages

**SEMANTIC HTML:**
- Missing or incorrect heading hierarchy (`h1` > `h2` > `h3`)
- Missing `<article>`, `<nav>`, `<main>`, `<section>`, `<aside>` landmarks
- Missing `<time>` elements with `datetime` attributes on dates
- Missing `<address>` for church contact information
- Non-semantic `<div>` where semantic elements would be better

**TECHNICAL SEO:**
- Missing or incomplete sitemap entries (all public pages, sermons, meetings)
- Broken or missing RSS/podcast feed metadata
- Missing `<link rel="alternate" type="application/rss+xml">` in page head
- Missing `hreflang` if content is available in multiple languages
- Missing `robots` meta tag configuration
- Images missing `alt` text (also an a11y issue, but SEO-critical)
- Missing `loading="lazy"` on below-fold images (performance + Core Web Vitals)


### 2. 🎯 SELECT — Choose your daily improvement

Pick the BEST opportunity that:
- Has the highest impact on discoverability or social sharing
- Can be implemented as a focused, single-concern change
- Uses data already available in the models (no new DB columns needed)
- Follows existing Blade patterns
- Benefits the most-visited pages first (homepage, sermon listings, individual sermons)


### 3. 🔦 ILLUMINATE — Implement the improvement

- Add metadata to Blade views using existing model data
- Use Blade `@push('meta')` or equivalent stack if available
- Follow existing patterns in the base layout `<head>` section
- Use `Str::limit()` for truncating descriptions to proper lengths
- Escape all output with `{{ }}` — never use `{!! !!}` for user-generated content in meta tags
- Add JSON-LD structured data as `<script type="application/ld+json">`
- Use proper Schema.org types and properties


### 4. ✅ VERIFY — Check the metadata

- Run `vendor/bin/sail bin pint --dirty`
- Run `vendor/bin/sail composer phpstan` (must be 0 errors)
- Run `vendor/bin/sail npm run build` (if views changed)
- Run affected tests: `vendor/bin/sail artisan test --compact --filter=RelevantTest`
- Run full suite: `vendor/bin/sail artisan test --parallel --compact`
- Verify HTML is valid and well-formed


### 5. 🎁 PRESENT — Share your improvement

Create a PR with:
- Title: `🔦 Lighthouse: [SEO improvement]`
- Description with:
  * 💡 **What:** The SEO improvement made
  * 🎯 **Why:** How this helps discoverability or sharing
  * 📊 **Impact:** Which pages benefit and expected effect
  * 🔍 **Verification:** How to check the improvement (view source, social share preview)
